# 大文件上传 Demo

对应简历里的课件上传链路，以及面试改进点「分片级 hash 校验」。

```
采样 Hash（头/中/尾 + 文件大小）
  → 秒传检查
  → 未命中则按 3～5MB 分片
  → 每片算 hash，最多 6 路并发上传
  → 后端对收到的字节再算一遍，对不上只重传该片
  → 合并前按清单再核一遍
```

## 运行

```bash
cd large-file-upload-demo
npm install
npm start
```

浏览器打开 http://127.0.0.1:3080

## 建议怎么测

1. 选一个 **20MB+** 的文件（或把分片调成 1MB 用小文件）。
2. 第一次走完整上传，看日志里的「后端校验通过」。
3. **再选同一个文件**：应命中秒传，不再传分片。
4. 勾选「模拟第 N 片传输出错」：前端带**原始 hash**，但把字节改坏。后端应 `CHUNK_HASH_MISMATCH`，前端只重传这一片。
5. 上传到一半点「中止」，再选同一个文件：会拉取已上传分片，只补缺失片（断点续传）。

## 和线上方案的差异（面试可主动说）

| 项 | 简历/线上 | 本 Demo |
| --- | --- | --- |
| 秒传指纹 | spark-md5 采样 | 同左，并拼进文件 size，降低误判 |
| 分片大小 | 3～5MB | 默认 4MB，可改 1～5MB 方便本地测 |
| 并发 | p-limit，最多 6 | 同等语义的限流器 |
| 分片校验 | 改进方向，当时没有 | Demo 已落地，合并失败可定位坏片 |
| 合并失败 | 清全部分片重传 | 返回坏片 index，只重传坏片 |

采样秒传仍可能碰撞（头中尾相同、中间不同）。分片 hash 解决的是**传输损坏定位**，不是秒传碰撞。
